# 给「不懂开发」的维护者：怎么把作业集放上站点

> 你只需要一个能打开网页的浏览器；下面的**方式 A** 还需要电脑上有这个仓库的文件夹 + Python。

---

## 方式 A：本地维护工具（最省事，推荐）

1. 打开仓库文件夹，**双击 `启动维护工具.bat`**；
2. 会弹出一个黑窗口（这个窗口要一直开着），浏览器自动打开「维护工具」页面；
3. 把作业集 `.json` 拖进虚线框 → 选阵型 / 填作者 / 可选填「这版改了什么」→ 点 **写入仓库**；
   - 作业集名和已有的**一致** = 给这套方案加一个新版本（旧版保留）；
   - 写成**新名字** = 新建一份作业集；
4. 页面下半部分可以随时改作者 / 说明、重命名、换阵型（每个作业集下面的「阵型」下拉 + 「移动」）、删除版本；
5. 全部弄完，用 GitHub Desktop 或命令行 `git add -A` → commit → push，1~2 分钟后站点更新。

> 工具只改本机的仓库文件，不会自动推送到线上；推送这一步还是要你来做（或者交给管理员）。
>
> 想先看看改完长什么样？双击 **`启动作业站预览工具.bat`**，浏览器会打开本地站点（只读，不影响任何文件）。

---

## 方式 B：线上网页向导（只需要浏览器 + GitHub 权限）

1. 让仓库管理员把你加成 **仓库协作者**（Settings → Collaborators → Add people）。
2. 打开站点首页，点右上角 **「上架作业集」**（网址：
   <https://daoyanxiaoz.github.io/maapvz-remote-assignment-set-integration/publish.html>）。

---

### B 的具体步骤

1. **拖文件**：把 MAAPVZ 编辑器导出的 `.json` 拖进虚线框（也可以点「选择文件」/「选择文件夹」）。
   一次拖多份也行。
2. **选导入方式**（每份文件单独选）：
   - **迭代作业集**：这是同一套方案的新改良版 → 旧版本会自动保留，站点多出一条历史记录。
   - **新建作业集**：这是一套全新的方案 → 站点多一个新作业集。
3. **填三件事**：
   - **阵型**：同类型打法的作业集放一起（例如 `心塔`）。下拉里没有就选「＋ 新建阵型…」并输入名字；
     不想归入任何阵型就选 **「（不归入阵型）」**，作业集照样能上架，只是卡片上没有阵型标签。
   - **版本日期**：默认今天，一般不用改。
   - **作者**：写你的名字（会显示在站点上）。**多个作者就用 `、` 隔开**，例如 `导演小z、某某`。
   - 顺带可以写「这版改了什么」，会显示在版本历史里。
4. 点 **「生成上架包」** → 下载得到 `上架包_xxx.bundle.json`。

### 把上架包传上去

1. 在浏览器打开仓库：<https://github.com/daoyanxiaoz/maapvz-remote-assignment-set-integration>
2. 点进 **`inbox`** 文件夹 → 右上角 **Add file → Upload files**。
3. 把刚才那个 `.bundle.json` 拖进去 → 下方 **Commit changes**。
4. 等 1~2 分钟：仓库的 **Actions** 会自动把作业集拆进 `jobs/` 并刷新站点索引。
   刷新首页就能看到你的作业集（记得 Ctrl+F5 强刷）。

> 没有权限传？把上架包直接发给仓库管理员，代传即可，效果完全一样。

> 上架时站点会**自动规整**你的作业集：局外选卡强制设成「自动选卡」，候选池只保留这套方案实际用到的植物。
> 所以你上传后文件内容和编辑器里导出会有点不一样，这是正常的。
>
> 写入结果里如果出现 `⚠`，说明这套作业集「可能已经有同名/同内容的一份」了——看一眼提示里的位置，
> 确认是想要新版本还是不小心传重复了。维护工具顶部的「仓库体检」也会列出这类问题。

## 常见问题

**Q：同一份作业集想再改一版怎么办？**
A：还是拖新文件 → 选「迭代作业集」→ 选它 → 版本日期填新日期 → 生成上架包 → 传 `inbox/`。
旧版本不会被覆盖，详情页的「版本历史」里能下载每一版。

**Q：传错了想撤掉？**
A：在 GitHub 里找到 `jobs/<阵型>/<作业集>/<日期>/` 整个目录删掉，然后在 Actions 页面手动跑一次
「重建作业集索引」。**不要**删整个作业集目录，除非你想把它从站点上撤下。

**Q：阵型名打错了 / 想改名？**
A：直接用维护工具里阵型那一行的「重命名阵型」；或者在 GitHub 里重命名 `jobs/` 下的阵型文件夹，
再手动跑一次「重建作业集索引」。

**Q：想删掉一个阵型，但不想把里面的作业集也删掉？**
A：点阵型那一行的「删除阵型」，弹窗里选 **「移到「不归入阵型」并删除阵型」** —— 阵型文件夹没了，
里面的作业集全部保留（只是不再挂在任何阵型下）。只有确实想连作业集一起清掉时，才选「连作业集一起删除」。

**Q：想把某个作业集换到别的阵型，或者让它不归入阵型？**
A：在维护工具里找到这个作业集，用下面那行的 **「阵型」下拉** 选中目标（没有合适的就选「＋ 新建阵型…」，
不想归入阵型就选「（不归入阵型）」），再点「移动」。**别手打阵型名**——以前手打会造出一堆奇奇怪怪的阵型。

**Q：多久生效？**
A：Actions 跑完 + Pages 部署，一般 1~3 分钟。看不到就强刷（Ctrl+F5）。

## 目录长什么样（记不住也没关系，向导会替你摆好）

```
jobs/
  心塔/                     ← 阵型
    失落原大火龙果/          ← 作业集
      2026-10-19/           ← 版本（创建日期）
        失落原大火龙果.json
        作者.txt
      2026-10-25/           ← 迭代出来的新版本
        失落原大火龙果.json
        作者.txt
        说明.txt
```

更多细节见 `docs/模板作业集/README.md` 与仓库根目录的 `交接文档.md`。
