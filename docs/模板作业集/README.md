# 模板作业集（只是说明书，不要放进 jobs/）

这就是一份「完整作业集」长得什么样：

```
我是一份作业集/                     ← 作业集目录（名字 = 站点上的作业集名）
  我是作业集的创建日期/              ← 版本目录（名字 = 版本日期，建议 YYYY-MM-DD）
    我是作业集文件.txt               ← 作业集本体：编辑器导出的 .json 放这里（.txt 也认）
    我的里面包含了作业集的作者名字.txt  ← 作者名，一行一个；多人就写多行（或一行用、隔开）
```

再往上还有一层「阵型」，用来把同类型的作业集放在一起（比如 `g心塔/`）——**这一层是可选的**：

```
jobs/
  我是一份作业集/                     ← 不归入阵型：作业集直接放在 jobs/ 下
    我是作业集的创建日期/              ← 版本（建议用日期 YYYY-MM-DD）
      我是作业集文件.txt
      我的里面包含了作业集的作者名字.txt
      说明.txt                     ← 可选：这一版改了什么

  g心塔/                             ← 阵型（g 开头）（可选）
    我是一份作业集/                    ← 作业集
      我是作业集的创建日期/             ← 版本
        我是作业集文件.txt
        我的里面包含了作业集的作者名字.txt
        说明.txt
```

同一份作业集想再迭代一版，就在它下面**再加一个日期目录**，旧版本不用动、也不会被覆盖。

> 阵型目录必须以 `g` 开头（`g心塔` → 站点显示「心塔」）；不带 `g` 的目录就是单个作业集。
> 版本目录建议用 `2026-10-19` 这种日期名字，版本历史里看起来最清楚。

> 线上不需要手工维护任何清单：`tools/build_index.py`（或 GitHub Actions）会扫描目录树生成 `index.json`。
> 想省事就用 <https://daoyanxiaoz.github.io/maapvz-remote-assignment-set-integration/publish.html> 的拖拽向导，
> 它会帮你把文件名、作者、日期都摆好。
