这是什么

玩家分享的 MAAPVZ 无尽模式作业集仓库。下载 JSON，导入编辑器即可复现别人的阵容与打法。
站点是纯静态页面（无后端、无数据库、无 CDN），靠 GitHub Pages 托管； 全部数据来自仓库里的 jobs/ 目录树。

站点怎么工作

jobs/<阵型>/<作业集>/<版本日期>/作业集文件 + 作者.txt ↑ 阵型层可选：不归入阵型就是 jobs/<作业集>/<版本日期>/ ↓ tools/build_index.py（本地维护工具会自动跑） index.json ← 站点唯一读的清单（阵型 / 作业集 / 版本历史 / 卡片字段） ↓ fetch index.html / job.html / publish.html
没有任何手写清单：目录树就是数据源。所以新人上架只需要放文件，不用改代码、不用改索引。

上架一份作业集（三条路）

  • 本地维护工具（最省事）：双击仓库根目录的 启动维护工具.bat → 浏览器里拖文件、改作者/说明、重命名、删版本，改完 commit + push。
  • 线上网页向导：打开 上架作业集 → 拖入文件 → 选「迭代」或「新建」→ 生成上架包 → 传到仓库 inbox/。
  • 命令行 / 手动：python tools/publish.py 作业集.json --group 心塔 --author 你的名字，或按目录约定直接放文件。
    • 上架时会自动规整：局外选卡强制「自动选卡」，候选池只保留这套作业集实际用到的植物（固定植物）。

    版本与历史

    一份作业集可以有很多版本：每次「迭代」都会在作业集目录下新增一个版本日期目录，旧版本原样保留。 详情页的「版本历史」列出每一版的作者、日期、说明和大小，任意一版都能单独下载。

    约定（维护者请遵守）

  • 阵型目录名 = 站点上的阵型名，例如 心塔、失落之城；可选 _group.json 补简介与排序。
  • 版本目录用创建日期 YYYY-MM-DD；同一天重复上架会自动加 _2，不会覆盖。
  • 作者.txt 写一行作者名；说明.txt 写这一版改了什么（可选）。
  • 作业集文件保持编辑器导出的样子即可，站点只用 textContent 渲染，不会执行里面的任何内容。
